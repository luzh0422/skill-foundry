# 视觉与信息规范

## 核心特征

从参考 Wiki 的 HWUI 管线、首次注册/逐帧引用、增量状态机和里程碑图提取：浅底深色标题；分区边界；圆角浅色节点；细描边；语义配色；外围正交连线；标题+职责两级文字；编号与图例。它是工程说明图，信息关系应先于装饰。

## 配色

`assets/style.json` 为执行时的默认值。色值来自画板节点样式，以较一致的 pipeline/state 为基础；architecture 使用同色相但略有差别，见 source-evidence。

## 六种布局

### 架构 / 管线

沿从上到下的阶段排大分区，每区内部从左到右。把同层独立分支放在一行并列，把关键依赖画到下一分区的具体节点。分区左上有小编号或标题条；底部图例解释路径颜色。主体是关系图，不能只是表格卡片。

### 跨进程传输

左右分别标生产者与消费者，中间画 IPC 箭头。首次注册与逐帧引用分成两条横区；共享载体用虚线或浅色外框，载体内用不同颜色标出结构、DrawOp、资源。箭头注明 memoryId/resourceId/fd/locator 等实际数据；不要把传描述误画成每帧复制整份正文。

### 状态机

主要状态横排；升级条件走卡片上方，处理完成回到复用态走下方。把“当前节点怎么处理”和“后代怎么处理”分别写在卡片内。首次进入点、自环、失败与返回转移按真实逻辑呈现；不同来源的边不能共用同一条不可辨识的线。

### 内存布局 / 生命周期

载体与内容分别用长条或分区；描述项指向 op 子范围，而不是指向整个 pool。空闲区可以浅色留白，已用区按内容类型着色。状态和内存图必须有分配 → 持有 → 释放 → freelist → 再分配/复用的闭环；若释放依赖多个 owner，画出最后引用条件。

### 结构前后对比

把旧/新方案或不同状态并列为结构快照，使用相同的信息层次方便横向比较。每列分别画对象的缓存关联、描述结构与字段、实际内容存储，用箭头指向被引用的具体内容。区分身份 ID、内容版本、数据定位和状态元数据；根据事实标出哪些改变、哪些保留，示意编号须注明。若方案涉及重新进入、恢复或复用，再加第三个状态快照。底部用简短说明写适用条件与边界，不能只画函数调用顺序。

### 里程碑

白底单水平轴，日期在轴上，空心或浅色圆点落在轴上，交付内容在下方短卡片。颜色区分阶段，不暗示没有来源的完成状态。未知日期用阶段名，避免照搬参考 Wiki 的时间与履历。

## 字体与密度

中文优先 Noto Sans CJK SC / Noto Sans SC，备用 Microsoft YaHei / PingFang SC。避免宋体和刻意混用字体。英文标识保持原拼写。

源画板字号范围约 13–43，但原图被文档缩放后小字可能难读。新图采用 1600 px 设计基线，将正文提升到约 20 px；这属于可读性适配，不声称参考源里所有文字都同一字号。

设画布宽 W：主标题约 0.024W，正文约 0.0125W；先用短语压缩说明，再扩宽卡片，最后才拆成第二张图。复杂架构宁可分“总览”和“局部设计”两张，勿把十个步骤压成一行小字。

## 验收

1. 标签、转移条件、单位与输入证据一致；截图里的指标不进入新图默认值。
2. 分区边界清楚，同色角色一致，连线具有明确起终点。
3. 文字未越界，箭头不经过正文，不出现遮住箭头的标签。
4. 自环、释放、取消或复用路径按语义完整呈现；结束回调与最后引用释放不同则分开。
5. 本地 SVG/PNG 都存在；远端发布后另检查实际画板预览。
