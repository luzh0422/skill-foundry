# 工程图表风格

先读取 [references/style-guide.md](references/style-guide.md)，按图的语义选布局；需要对照原样时，查看 [references/source-evidence.md](references/source-evidence.md) 和 `assets/reference-*.png`。把风格用于新内容，勿照搬原 Wiki 的技术结论、履历、指标或项目日期。

## 工作流程

1. **确定图意。** 用一句话写清读者需要理解什么；提取阶段、对象、输入/输出、状态条件和释放点。优先读取用户提供的代码或事实依据。保留用户给定的名称、单位和数字；信息缺失时标明，不编造。
2. **选择布局。** 阶段流程采用横向分区泳道；跨进程采用两端分栏和显式边界；状态机采用横排状态、上方升级边、下方返回边；结构前后对比采用并列快照，明确对象关联、描述字段与实际内容存储；内存图分别画载体、描述清单和内容区，并补回收复用环；计划采用单轴里程碑。不要把每种图都画成同一套卡片网格。
3. **应用语义配色。** 用 `assets/style.json`。蓝色表示结构/主路径，紫色表示独立层/分支，绿色表示内存/资源，金色表示命令/提交准备，珊瑚色表示事务/交接，灰色表示基础设施。状态机可用绿=复用、蓝=局部处理、金=重建；必须有文字标签，不仅靠颜色。
4. **制作图。** 模板适配时使用下方脚本。布局复杂时直接创作 SVG，沿用样式值，使用正交折线、清晰的分区标题和两级卡片文字。把复用、释放、回收边画出来；箭头标签写动作/数据，不写无意义的“调用”。
5. **验证。** 解析 SVG，渲染 PNG，使用 `view_image` 目视检查全图以及密集区。检查卡片、文字、连线是否重叠；检查返回边、分支条件与代码一致。修复后重渲染；SVG XML 通过不代表画面通过。
6. **交付。** 交付 SVG、PNG，以及 JSON spec 或 SVG 源文件。回复链接并概述图意。用户要求写入文档时，再调用对应文档技能执行已授权写入，回读并导出预览检查。

## 快速生成

设置 `SKILL_ROOT` 为本技能目录。复制一个模板到本次工作目录，修改事实和标签，创建输出目录，再运行：

```bash
python3 "$SKILL_ROOT/scripts/draw_diagram.py" \
  --spec ./diagram.json --svg ./diagram.svg --png ./diagram.png
```

脚本只写指定输出。SVG 生成为 Python 标准库实现；PNG 需要本机 Chrome/Chromium 和 Pillow，以及可显示中文的字体。支持 `--chrome /path/to/chrome`。无 PNG 依赖时 SVG 会先保存，随后报出缺口；根据实际环境安装到临时位置或使用现有渲染器，勿修改系统环境作为默认行为。

| 模板 | 用途 | 支持范围 |
|---|---|---|
| `assets/lanes.example.json` | 架构 / 分阶段数据流 | 1–5 个泳道；每道 1–4 个顺序节点；泳道间依赖需在自定义 SVG 中明确添加 |
| `assets/state.example.json` | 升级、处理与复用闭环 | 3 个状态；相邻前进边、上/下外部通道；更多状态与自环需自定义 |
| `assets/timeline.example.json` | 项目里程碑 | 2–5 个节点；日期必须有来源，未知时用阶段名 |

JSON 字段与自定义绘制方法见 [references/template-contract.md](references/template-contract.md)。脚本限制只是模板能力边界，勿为套模板改变业务语义。

## 呈现约束

- 以 1600 px 宽画布设计；按内容选择高度，优先宽图。默认 48 px 外边距、20–32 px 卡片内边距、48–72 px 连线通道。不要保留原画板导出产生的大片空白。
- 使用深蓝黑标题、浅灰蓝底、白色分区和低饱和填充。线宽约 2–2.5 px，圆角约 8–20 px。允许一个简洁标题色条；不用装饰性阴影、渐变、复杂背景。
- 在 1600 px 画布中，标题 36–42 px，分区标题 24–28 px，节点名 22–24 px，正文 19–22 px，注释不低于 18 px。不要通过缩小字体解决拥挤，优先删冗余、放大卡片或拆图。
- 保留英文类名/方法名；中文写职责与条件。每张卡片用一个节点名和 1–3 行说明；较长代码标识宁可扩宽卡片，不要逐字符硬折断。
- 直连沿阅读方向；跨区、反馈、回收边使用外围折线。给重要分支与返回边留独立通道。按需要标明①②③步骤和底部图例。
- 以脚本中的浅色体系作为默认。只有强调最终消费端/关键汇聚点时使用深色填充+白字，且每图不超过两个。状态优先级必须写条件，不能只凭颜色推断。

## 跨工具输出

把 `assets/style.json` 的颜色、字号比例、圆角、边距和连线规则作为通用规范；按目标工具选择输出格式。默认交付 SVG 源文件和 PNG 预览，保留生成用的 JSON spec 或代码。

| 目标 | 使用方式 | 编辑能力 |
|---|---|---|
| Markdown / 本地文档 / 其他 Wiki | 插入 PNG；支持 SVG 的查看器可直接引用 SVG | 图形修改回到 SVG 或生成代码 |
| PPT / Word | 插入 PNG，或使用该版本支持的 SVG | SVG 是否能转换为可编辑形状取决于软件版本；PNG 不能逐节点编辑 |
| 网页 / HTML | 嵌入 SVG，或使用 PNG 图片 | SVG 元素可由代码控制；交互需另行实现 |
| Inkscape / Figma 等 SVG 编辑器 | 导入 SVG，核对字体、分组和箭头 | 可编辑程度取决于导入器，须检查实际结果 |
| draw.io / diagrams.net | 以 SVG/PNG 插入图片；需要原生节点时按规范生成 `.drawio` | 图片导入不等于原生节点，不能承诺逐卡片编辑 |
| Mermaid 等文本绘图工具 | 映射语义配色到 theme/classDef，并设置字体与线条 | 保留可编辑源码，但自动布局不保证复现 SVG 的精确布局 |

现有脚本直接生成 SVG/PNG。用户要求原生可编辑 PPTX、draw.io 或工具节点时，使用目标工具的技能或接口制作原生对象，再按本技能的视觉规范验收；不要把嵌入图片当作原生可编辑交付。只有用户要求写入目标工具时才执行相应写入，并检查最终渲染。

## 发布到飞书

把本技能用于样式和图源生成，把 `lark-doc` / `lark-whiteboard` 用于内容写入与远端验证。SVG 适合保留这种分区布局；无样式默认 Mermaid 常会丢失卡片层次与颜色，不作为“风格一致”的完成证据。SVG 转成画板可能改变字体和箭头，必须检查远端预览。

用户授权画图不自动授权覆盖已有画板。遵循用户本次指定目标和相应技能的修改规则；更新已有画板保留其 token。用户只要求本地图时，交付本地文件即可。
